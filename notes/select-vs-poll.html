select 與 poll：等待 I/O 就緒

用一個等待點監看多個 fd，分清 select 的集合與 poll 的事件陣列，避免把就緒誤認為傳輸完成。

01快速摘要 Quick Summary

select() 與 poll() 都是 I/O multiplexing（I/O 多工）介面：同時等待多個 fd，並回報哪些可以進行 I/O。它們不會替你讀寫資料；select() 使用 fd 集合，poll() 使用事件陣列。

02核心觀念 Core Concepts

01 / 就緒，表示現在可以嘗試 I/O

直接對沒有資料的阻塞式 fd 呼叫 read，可能一直等待。I/O 多工先等待一組 fd 的狀態，讓單一行程能處理多個來源，不必卡在其中一個。

可讀不一定代表有資料：EOF 也可能被回報為可讀，這時 read 會回傳 0。就緒不保證讀滿你要求的長度，也不保證一次 write 能寫完任意大小的資料；正式事件迴圈通常搭配 nonblocking I/O，處理 EAGAIN、短讀與短寫。

02 / 介面的差異

select 與 poll 的重點比較
比較項目selectpoll
監看資料結構讀、寫、例外三組 fd_setstruct pollfd 陣列
數量參數nfds = 最大 fd + 1nfds = 陣列元素個數
結果放哪裡原集合被改成就緒子集合每個元素的 revents
逾時timeval，秒 + 微秒；NULL 表示無限等待整數毫秒；負數表示無限等待
不等待timeval 兩欄都為 0timeout = 0
fd 限制fd 必須小於 FD_SETSIZE；Linux/glibc 通常為 1024無 fd_set 的固定編號限制，仍受系統資源限制

select 每次呼叫前要重建集合與 timeout：集合會被修改，timeout 在不同平台的處理也有差異。poll 的 events 是要求監看的事件，revents 是本次回報的結果；同時有多個事件時，要用位元運算 & 檢查。

兩者回傳 -1 表示錯誤，0 表示逾時，正數表示有就緒結果。select 的正數是三個結果集合內設定位元的總數，同一個 fd 在不同集合可能重複計入；poll 則計算 revents 非零的陣列元素數。

03 / 就緒以後仍要處理邊界情況

  • EINTR：等待可能被訊號打斷。若要重試，需重建輸入資料；若有總時間限制，還要依剩餘時間計算逾時。
  • POLLHUP：對方已掛斷，但可能還有尚未讀出的資料，常與 POLLIN 同時出現。
  • POLLERR / POLLNVAL：分別表示錯誤狀態或無效 fd；即使沒有放入 events，也可能出現在 revents。
  • 規模：poll 不代表任何情況都比較快。兩者通常都需要隨監看範圍或陣列長度掃描；大量連線可再研究 Linux 的 epoll 或 BSD/macOS 的 kqueue。

03程式範例 Code Example

下面是兩支可各自編譯的 POSIX 程式，都等待標準輸入最多約 5 秒，只回報狀態，不讀取內容，讓介面差異更清楚。一般終端機採 canonical mode，請輸入文字後按 Enter。

C / wait-select.c

#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <sys/select.h>
#include <unistd.h>

int main(void)
{
    int fd = STDIN_FILENO;
    if (fd >= FD_SETSIZE) {
        fputs("fd exceeds fd_set capacity\n", stderr);
        return 1;
    }
    fd_set reads;
    FD_ZERO(&reads);
    FD_SET(fd, &reads);
    struct timeval timeout = { .tv_sec = 5, .tv_usec = 0 };

    int n = select(fd + 1, &reads, NULL, NULL, &timeout);
    if (n == -1) { perror("select"); return 1; }
    if (n == 0) { puts("timeout"); return 0; }
    if (FD_ISSET(fd, &reads))
        puts("stdin readable: data or EOF (use read to check)");
    return 0;
}

C / wait-poll.c

#define _POSIX_C_SOURCE 200809L
#include <poll.h>
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    struct pollfd item = {
        .fd = STDIN_FILENO, .events = POLLIN, .revents = 0
    };
    int n = poll(&item, 1, 5000);
    if (n == -1) { perror("poll"); return 1; }
    if (n == 0) { puts("timeout"); return 0; }

    if (item.revents & POLLNVAL) {
        fputs("invalid fd\n", stderr);
        return 1;
    }
    if (item.revents & POLLERR) {
        fputs("I/O error event\n", stderr);
        return 1;
    }
    if (item.revents & POLLIN)
        puts("stdin readable: use read to inspect data or EOF");
    if (item.revents & POLLHUP)
        puts("hangup: drain remaining data before closing");
    return 0;
}

SHELL / 編譯與操作

cc -std=c11 -Wall -Wextra -Wpedantic wait-select.c -o wait-select
cc -std=c11 -Wall -Wextra -Wpedantic wait-poll.c -o wait-poll
./wait-select
./wait-poll

每次啟動後，在 5 秒內輸入文字並按 Enter，會看到 stdin readable: ...；若沒有輸入、EOF 或其他事件，會印出 timeout。排程可能讓實際等待略超過指定時間。

也可執行 printf 'hello\n' | ./wait-select 或 printf 'hello\n' | ./wait-poll。poll 可能同時回報 readable 與 hangup，取決於寫端是否已關閉；事件組合不應被假設固定。

為保持範例聚焦，遇到包含 EINTR 在內的等待錯誤會印出訊息並結束。實際事件迴圈需重試、移除失效 fd，並呼叫 read／write 處理資料；poll 範例的錯誤分支採取直接結束的策略。

04常見錯誤 Common Mistakes

  • 「select 的 nfds 是監看數量」：它是最大 fd 加一；poll 才傳入陣列元素數。
  • 「select 的集合能直接重用」：回傳後只剩就緒項目，下一輪必須重建。
  • 「poll 的 timeout 單位是秒」：單位是毫秒，5000 才是 5 秒。
  • 「revents == POLLIN 就夠了」：事件是 bitmask，應用 revents & POLLIN，並另外檢查掛斷與錯誤。
  • 「就緒就代表資料已讀完」：它只回報狀態，仍需執行 I/O，判斷 EOF 與錯誤。

05重點整理 Key Takeaways

  1. 兩者都是等待就緒的工具，不負責實際資料傳輸。
  2. select 用集合與最大 fd + 1；poll 用陣列與元素數。
  3. select 的集合與逾時要重建，poll 要檢查 revents 位元。
  4. 就緒仍可能遇到 EOF、短讀、短寫或狀態變化。
  5. 處理 EINTR、掛斷與錯誤，才能建立可靠的事件迴圈。
