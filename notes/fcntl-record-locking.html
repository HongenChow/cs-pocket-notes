fcntl() Record Locking

鎖住一段位元組，讓多個行程協調讀寫；從鎖的範圍到生命週期，一次理清。

01快速摘要 Quick Summary

Record locking（記錄鎖定）讓行程透過 fcntl() 對檔案的某段位元組設定讀鎖或寫鎖，不必鎖住整份檔案。本文介紹傳統 POSIX、與行程關聯的 advisory lock（建議式鎖）：參與者必須遵守相同的鎖定協定，才能協調存取。

02核心觀念 Core Concepts

01 / Record 是應用程式定義的資料範圍

核心只認得 byte range（位元組範圍），不會自動辨識文字行或 C 的結構。例如每筆資料佔 100 bytes，從 0 編號的第 2 筆資料就位於 bytes 200～299；行程可只鎖這一段，其他不重疊的範圍仍可獨立鎖定。

Advisory lock 不會強迫未配合的行程停止 read() 或 write()。所有參與者都應先取得適當的鎖，再存取資料，完成後才解鎖。

02 / 讀鎖共享，寫鎖互斥

不同的行程對同一檔案之重疊範圍提出鎖定要求
已持有的鎖要求讀鎖 F_RDLCK要求寫鎖 F_WRLCK
讀鎖 F_RDLCK相容，可同時持有衝突
寫鎖 F_WRLCK衝突衝突

F_RDLCK 是 shared lock，fd 必須允許讀取；F_WRLCK 是 exclusive lock，fd 必須允許寫入。使用 O_RDWR 開啟檔案可申請兩種鎖；F_UNLCK 則用來解除指定範圍的鎖。

03 / 用 struct flock 描述範圍

  • l_type：指定 F_RDLCK、F_WRLCK 或 F_UNLCK。
  • l_whence：l_start 的基準；SEEK_SET 為檔案開頭，SEEK_CUR 為目前 file offset，SEEK_END 為目前檔案結尾。
  • l_start：相對於基準的起點位移，以 byte 為單位。
  • l_len：正值表示鎖定的位元組數；例如基準為開頭、起點 200、長度 100，範圍是 200～299。0 表示從起點延伸至檔案結尾，包含之後增長的部分，不是不鎖任何資料。
  • l_pid：使用 F_GETLK 查到衝突的傳統鎖時，用來回報持鎖行程的 PID；不是設定鎖擁有者的輸入欄位。

建議先以 struct flock lock = {0}; 初始化，再逐一設定欄位。使用 SEEK_SET 可讓範圍不受目前 file offset 影響；鎖定本身不會移動 file offset，也不會自動讀寫資料。

04 / 設定、等待與查詢

fcntl(fd, cmd, &lock) 的三種常用命令
cmd用途與衝突時的行為
F_SETLK設定鎖或解鎖；遇到衝突不等待鎖釋放，回傳 -1，errno 為 EACCES 或 EAGAIN，應同時檢查兩者。
F_SETLKW設定鎖或解鎖；申請鎖遇到衝突時等待，直到可取得鎖。等待可能被訊號中斷而回報 EINTR，也可能因偵測到死結而回報 EDEADLK。
F_GETLK查詢假設的鎖定要求是否衝突；不會取得鎖。無衝突時將 l_type 設成 F_UNLCK；有衝突則回填其中一把衝突鎖的資訊。

以上命令成功時回傳 0，失敗回傳 -1 並設定 errno。F_GETLK 的結果只是當下資訊，查詢後仍可能被別的行程搶先取得鎖；真正的互斥必須靠成功的鎖定操作。

05 / 鎖屬於行程，close 的影響比想像中大

傳統 record lock 屬於行程與檔案的關係。同一行程對已鎖定範圍重新設鎖，可能轉換、分割或合併既有鎖；不會像兩個獨立行程一樣互相阻擋，因此也不能拿它當同一行程內的 thread mutex。

  • fork() 會繼承 fd，但子行程不會繼承父行程的傳統 record lock；子行程若要存取受保護範圍，應自行申請鎖。
  • 行程只要 close() 任一個指向該檔案的 fd，該行程在此檔案上的所有傳統 record locks 都會釋放，即使關掉的不是最初設鎖的 fd。這也適用於 dup 得到的 fd 或另外 open 同一檔案的 fd。
  • 行程結束也會釋放鎖；正常路徑仍應明確使用 F_UNLCK，讓臨界區的界線清楚。

本文不涵蓋 F_OFD_* 的 open file description locks；其擁有者與生命週期不同，不能直接套用上述規則。struct flock 是此處的資料結構，也不要與另一個系統呼叫 flock() 混為一談。

03程式範例 Code Example

在 Linux、macOS 或 WSL 的 POSIX 環境，將下列程式存為 fcntl-record-locking.c。它以寫鎖保護 bytes 0～99，等待使用者按 Enter 後解鎖；只示範臨界區的取得與釋放，不修改檔案內容。

C / fcntl-record-locking.c

#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s FILE\n", argv[0]);
        return 1;
    }
    int fd = open(argv[1], O_RDWR | O_CREAT, 0600);
    if (fd == -1) { perror("open"); return 1; }

    struct flock lock = {0};
    lock.l_type = F_WRLCK;
    lock.l_whence = SEEK_SET;
    lock.l_start = 0;
    lock.l_len = 100;

    int result = 1;
    puts("waiting for write lock on bytes 0-99...");
    fflush(stdout);
    while (fcntl(fd, F_SETLKW, &lock) == -1) {
        if (errno == EINTR) continue;
        perror("fcntl lock");
        goto done;
    }

    puts("locked; press Enter to unlock");
    fflush(stdout);
    /* Protected file I/O would go here, before unlocking. */
    int ch;
    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
    if (ferror(stdin)) {
        perror("getchar");
        goto done;
    }

    lock.l_type = F_UNLCK;
    if (fcntl(fd, F_SETLK, &lock) == -1) {
        perror("fcntl unlock");
        goto done;
    }
    puts("unlocked");
    result = 0;

done:
    if (close(fd) == -1) { perror("close"); result = 1; }
    return result;
}

SHELL / 編譯與執行

cc -std=c11 -Wall -Wextra -Wpedantic fcntl-record-locking.c -o fcntl-record-locking
./fcntl-record-locking lock-demo.dat
  1. 在終端機 A 執行程式，會印出等待訊息，接著印出 locked; press Enter to unlock，此時先不要按 Enter。
  2. 在終端機 B 切到同一個目錄，執行同一個命令並指定同一檔案。B 只印出等待訊息，阻塞在 F_SETLKW。
  3. 在 A 按 Enter，A 解鎖並印出 unlocked；B 才能取得鎖並印出 locked 訊息。再於 B 按 Enter 結束。

O_CREAT 會在檔案不存在時建立它，沒有 O_TRUNC 因此不清空既有內容。即使檔案是空的，也可以鎖定 bytes 0～99；鎖定不會使檔案增長。stdin 若已到 EOF，程式會直接進入解鎖步驟，因此互動測試時請保留終端機輸入。

可將取得鎖的命令改成 F_SETLK，比較 B 遇到衝突時立即失敗的行為。實際程式應分辨 EACCES／EAGAIN 與其他錯誤；本範例以 perror() 顯示失敗原因並結束。

實際更新資料時，應將完整的「讀取 → 計算 → 寫回」放在持有寫鎖的區間，並處理短讀、短寫與錯誤。若使用會緩衝的 stdio 寫入，必須在解鎖前成功 fflush()；鎖本身不等於資料已同步到磁碟。

04常見錯誤 Common Mistakes

  • 「鎖住後，任何行程都不能寫」：advisory lock 只協調有配合鎖定協定的參與者，無法阻止刻意繞過鎖的 I/O。
  • 「l_len = 0 代表零長度」：它表示鎖到結尾並涵蓋之後的增長；若只保護一筆資料，應明確填入範圍。
  • 「F_GETLK 顯示可用，就能直接寫」：查詢不會保留鎖，仍有 race condition；應先成功取得鎖。
  • 「fork 或 dup 後，每個 fd 都有獨立的鎖」：傳統鎖與行程關聯；fork 的子行程不繼承鎖，而同一行程 close 任一指向該檔案的 fd 都會釋放該檔案上的所有傳統鎖。
  • 「只鎖最後的 write 就夠」：若先讀後改，讀取到寫回之間都應受保護，否則可能發生 lost update。
  • 「F_SETLKW 一定會成功」：等待仍可能失敗；檢查 EINTR、EDEADLK 等錯誤，多範圍鎖定時讓所有行程遵守一致的取得順序以降低死結風險。

05重點整理 Key Takeaways

  1. Record locking 針對 byte range；advisory lock 需要所有參與者配合。
  2. 重疊範圍內，讀鎖可共享，寫鎖與其他行程的讀寫鎖互斥。
  3. 用 struct flock 指定類型與範圍；l_len 為 0 會鎖到結尾並涵蓋後續增長。
  4. F_SETLK 不等待衝突鎖釋放，F_SETLKW 會等待；F_GETLK 只查詢，不取得鎖。
  5. 傳統鎖屬於行程，不由 fork 繼承；close 任一指向該檔案的 fd 或結束行程，都會釋放該行程在此檔案上的傳統鎖。
