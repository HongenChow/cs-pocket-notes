fork 與 exit：行程的建立與結束

看懂 fork 的兩條執行路徑，分清 exit 與 _exit，並用 waitpid 取得子行程的結束狀態。

本篇目錄

  1. 01 快速摘要
  2. 02 核心觀念
  3. 03 程式範例
  4. 04 常見錯誤
  5. 05 重點整理

01快速摘要 Quick Summary

fork() 成功後，父、子行程都從呼叫之後繼續執行，並用不同回傳值區分角色。exit() 會進行 C 函式庫的結束清理，_exit() 不刷新 stdio 緩衝；父行程通常用 waitpid() 取得子行程狀態並完成回收。

02核心觀念 Core Concepts

01 / 一次 fork，兩條路徑

fork() 的回傳值與角色
回傳值目前角色如何處理
-1建立失敗，只有原行程檢查 errno，不會產生子行程
0子行程執行子行程分支
大於 0父行程回傳值是新子行程的 PID

父、子行程有各自的普通變數與位址空間；子行程修改普通變數，不會直接改動父行程那份。繼承的 fd 則指向相同的 open file description，因此可能共享檔案位移。明確建立的共享記憶體是另一種機制。

作業系統的排程決定誰先執行，不能假設父行程一定先跑。fork() 建立新行程，exec 家族則用新程式替換目前行程的程式映像；兩者常配合使用。

02 / exit 與 _exit 差在哪裡？

正常結束與直接結束的比較
方式atexit 處理函式刷新 stdio 緩衝
exit(status)會呼叫會
return status（從 main）等同正常 exit 流程會
_exit(status)不會呼叫不會

_exit() 仍會關閉行程的開啟描述符，不等於「核心完全不清理」。它適合用在 fork 後即將結束的子行程路徑，例如 exec 失敗後，避免重跑父行程的 C 層清理。

為什麼訊息可能印兩次？fork 會複製尚未送出的使用者空間 stdio 緩衝。若兩邊都呼叫 exit，可能各自刷新同一份內容。單執行緒程式可在 fork 前 fflush()；子行程使用 _exit 時，自己的 printf 緩衝也不會自動送出。

03 / 結束不等於已回收

在一般父子行程與預設訊號處理下，子行程結束後，核心仍保留狀態供父行程讀取，這段期間稱為 zombie（殭屍行程）。waitpid(pid, &status, 0) 等待指定子行程結束並取回狀態；若已結束，便可立即回收。

status 是編碼後的資訊，先以 WIFEXITED(status) 判斷正常結束，再用 WEXITSTATUS(status) 取出低 8 位元的結束碼。若被訊號終止，改用 WIFSIGNALED 與 WTERMSIG。

03程式範例 Code Example

以下是單執行緒 POSIX 程式。父行程先刷新 stdout，子行程以狀態碼 7 結束，父行程等待並解碼結果。

C / fork-and-exit.c

#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <stdio.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
    puts("before fork");
    if (fflush(stdout) == EOF) { perror("fflush"); return 1; }

    pid_t pid = fork();
    if (pid == -1) { perror("fork"); return 1; }
    if (pid == 0) {
        /* 子行程：不刷新繼承的 stdio 緩衝。 */
        _exit(7);
    }

    int status;
    pid_t waited;
    do {
        waited = waitpid(pid, &status, 0);
    } while (waited == -1 && errno == EINTR);
    if (waited == -1) { perror("waitpid"); return 1; }

    if (WIFEXITED(status)) {
        printf("child exit=%d\n", WEXITSTATUS(status));
    } else if (WIFSIGNALED(status)) {
        printf("child signal=%d\n", WTERMSIG(status));
    }
    return 0;
}

SHELL / 編譯與執行

cc -std=c11 -Wall -Wextra -Wpedantic fork-and-exit.c -o fork-and-exit
./fork-and-exit

預期輸出：

before fork
child exit=7

7 是子行程的結束碼；父行程最後 return 0，所以 shell 觀察到整個範例的結束碼仍是 0。waitpid 被訊號中斷而回傳 EINTR 時，範例會重試。

多執行緒的額外限制：多執行緒行程 fork 後，子行程在 exec 前只能呼叫 async-signal-safe 函式。不要把 printf、exit 或一般函式庫清理直接搬進這段路徑；本範例的子行程只呼叫 _exit。

04常見錯誤 Common Mistakes

  • 「fork 回傳 0 代表失敗」：0 代表自己是子行程，-1 才是失敗。
  • 「子行程從 main 重新執行」：它從 fork 呼叫之後繼續。
  • 「exit 只關閉行程，不會處理緩衝」：它會執行 atexit 處理函式並刷新 stdio，可能造成重複輸出。
  • 「waitpid 回傳值就是結束碼」：成功時回傳子行程 PID，結束資訊寫入 status，須以巨集解碼。
  • 「sleep 一下就等於同步」：sleep 不保證子行程已完成；要用 waitpid 或合適的同步機制。

05重點整理 Key Takeaways

  1. fork 的 -1、0、正數分別對應失敗、子行程、父行程。
  2. 普通記憶體各自獨立，繼承的 fd 卻可能共享開啟狀態。
  3. exit 會做 C 層清理；_exit 不刷新 stdio 緩衝。
  4. 父行程使用 waitpid 回收子行程，不能靠排程順序猜測完成時間。
  5. 先判斷 WIFEXITED，再讀取 WEXITSTATUS。
