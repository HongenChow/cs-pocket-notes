檔案位移：下一次從哪裡讀？

從 read、lseek 到 dup，理解 file offset 儲存在哪裡，以及為什麼不同 fd 會互相影響。

本篇目錄

  1. 01 快速摘要
  2. 02 核心觀念
  3. 03 程式範例
  4. 04 常見錯誤
  5. 05 重點整理

01快速摘要 Quick Summary

File offset（檔案位移）是可定位檔案下一次讀寫的位元組位置，從 0 開始計算。它屬於核心中的 open file description；透過 dup() 或 fork() 取得的相關描述符會共享它。

02核心觀念 Core Concepts

01 / 分清三個層次

  • File descriptor（fd）：行程持有的非負整數，例如 3，用來引用已開啟的檔案。
  • Open file description：核心維護的一次開啟狀態，包含 file offset 與檔案狀態旗標。
  • 檔案本身：實際儲存的資料。同一個檔案可有多個獨立的開啟狀態。

fd ─┐
copy ─┴→ 同一個 open file description → 檔案資料
這是 dup(fd) 的情況：兩個引用，共享一個 offset。

02 / read 與 lseek 如何移動位置？

對一般檔案，成功的 read(fd, buf, n) 會從目前 offset 開始，並依實際讀到的位元組數前進；回傳值不一定等於 n。要求讀取的長度大於 0 時，回傳 0 表示 EOF，-1 表示錯誤。

lseek(fd, offset, whence) 的三種定位基準
whence新的位置例子
SEEK_SET檔案開頭 + offsetlseek(fd, 0, SEEK_SET) 回到開頭
SEEK_CUR目前位置 + offsetlseek(fd, 2, SEEK_CUR) 向前跳 2 bytes
SEEK_END檔案大小 + offsetlseek(fd, 0, SEEK_END) 移到結尾

lseek() 成功時回傳新的 off_t 位移，失敗回傳 (off_t)-1。單純定位不會讀寫資料，也不會改變檔案大小；pipe、FIFO、socket 通常不能用它定位。

03 / 什麼情況共享 offset？

dup(fd) 與 fork() 後繼承的 fd 會指向同一個 open file description。相反地，對同一路徑各自呼叫兩次 open()，會有兩個獨立的 offset；共享檔案資料，不代表共享讀寫位置。

03程式範例 Code Example

範例先讀出 A，再從複製的 fd 讀出 B；接著透過原 fd 將位置設為 3，從複製的 fd 讀到 D。請在 Linux、macOS 或 WSL 的 POSIX 環境執行。

C / file-offset.c

#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>

static int read_one(int fd, char *ch)
{
    ssize_t n;
    do {
        n = read(fd, ch, 1);
    } while (n == -1 && errno == EINTR);
    if (n == -1) { perror("read"); return -1; }
    if (n == 0) { fputs("file too short\n", stderr); return -1; }
    return 0;
}

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s FILE\n", argv[0]);
        return 1;
    }
    int fd = open(argv[1], O_RDONLY);
    if (fd == -1) { perror("open"); return 1; }
    int copy = dup(fd);
    if (copy == -1) { perror("dup"); close(fd); return 1; }

    int result = 1;
    char a, b, d;
    if (read_one(fd, &a) == -1) goto done;
    if (read_one(copy, &b) == -1) goto done;
    if (lseek(fd, 3, SEEK_SET) == (off_t)-1) {
        perror("lseek");
        goto done;
    }
    if (read_one(copy, &d) == -1) goto done;
    printf("first=%c second=%c after_seek=%c\n", a, b, d);
    result = 0;
done:
    if (close(copy) == -1) { perror("close copy"); result = 1; }
    if (close(fd) == -1) { perror("close fd"); result = 1; }
    return result;
}

SHELL / 建立測試資料、編譯與執行

printf 'ABCDE' > sample.txt
cc -std=c11 -Wall -Wextra -Wpedantic file-offset.c -o file-offset
./file-offset sample.txt

預期輸出：first=A second=B after_seek=D。請在測試用目錄操作；第一行會建立或覆寫 sample.txt。

  1. 初始 offset 是 0，第一個 read 讀到 A，位置變成 1。
  2. copy 共用位置，所以讀到 B，位置變成 2。
  3. lseek 將共享位置改成 3，下一次讀到 D，最後位置為 4。

範例只讀一個 byte，並處理 EINTR。正式的多位元組讀寫程式還要處理短讀、短寫；不要假設一次呼叫會完成全部資料。

04常見錯誤 Common Mistakes

  • 「offset 存在 fd 整數裡」：fd 只是引用，位置保存在 open file description。
  • 「同一個檔案就一定共享位置」：兩次 open 各自建立狀態，dup 才是共享既有狀態。
  • 「read 要求多少，就前進多少」：應依回傳的實際位元組數判斷。
  • 「每個 fd 都能 lseek」：pipe 等串流沒有可任意定位的檔案位置，要檢查錯誤。
  • 「offset 就是第幾個中文字」：offset 以 byte 計算；UTF-8 字元可能佔多個 bytes。

05重點整理 Key Takeaways

  1. File offset 是下一次讀寫的位置，以 byte 為單位。
  2. 位置屬於 open file description，dup 與 fork 可以共享它。
  3. 分別 open 同一個檔案，offset 仍然獨立。
  4. read 依實際讀取量前進；lseek 只調整位置。
  5. 先確認檔案可定位，並檢查每次系統呼叫的回傳值。
